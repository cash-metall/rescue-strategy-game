# Архитектура

Вся игра — один файл `rescue-hq.html`: `<style>` (CSS), разметка шапки/карты/панелей, и один
`<script>` с логикой. Ни сборки, ни модулей, ни зависимостей. Ниже — как это работает.

## Два объекта состояния

### `G` — состояние текущего дела
Пересоздаётся функцией `newGame(camp)` → `tryGen(camp)` на каждое новое дело. Ключевые поля:

- `t` — игровое время в минутах (старт 0 = 08:00 первого дня).
- `funds`, `incAcc`, `spent` — деньги, накопитель пассивного дохода, всего потрачено.
- `weather`, `weatherNext`, `nextEvent` — погода и таймеры смены погоды/событий.
- `map[y][x]` — сетка клеток `{x,y,terrain,coverage,objects[],touched}`.
- `profile`, `lkp`, `path`, `trailSet`, `victim`, `drainBase`, `hq` — пропавший, точка последнего
  контакта, маршрут, множество клеток маршрута, позиция/состояние жертвы, скорость падения сил,
  координаты лагеря (дублируются в модульной `let HQ`, которую `tryGen` задаёт под каждое дело —
  лагерь ставится в 2–3 клетках от ТПК).
- `buildings{tent,radio,carto,rest,train}` — уровни построек.
- `units[]` — отряды `{id,type,gen,name,level,fatigue,status,phaseStart,phaseEnd,mission}`.
- `clues[]` — собранные улики (см. systems.md).
- `expRuns[]`, `expQueue[]` — активные и ожидающие экспертизы.
- `log[]`, `stats{cluesTotal,cluesReal}`, `over` (null | `{win,by}`), `paused`.
- `ui{tab,sel,selUnits(Set),dur,heat,speed}` — состояние интерфейса.

### `campaign` — мета-прогресс между делами
Отдельный объект, живёт в `localStorage`. Формат и правила — в [campaign.md](campaign.md).
`G` берёт из него постройки, ростер, счётчики нанятых и статистику при генерации дела.

Хелперы-геттеры над `G` собраны в секции ДОСТУП: `cellAt`, `clueById`, `unitById`, `effMark`,
`hourOf`, `isNight`, `activeMissions`, `inRange`, `targetable`, `fatEff`, `lvlPow/lvlSpd/lvlFat`,
`searchEff`, `travelTime`. Используйте их, а не лезьте в поля напрямую.

## Игровой цикл

```
setInterval(tick, 250)   // 4 реальных тика в секунду
```

`tick()`:
1. Если не пауза и не конец — прогоняет `simMinute()` ровно `G.ui.speed` раз (скорость 1/2/4).
2. `renderHeader()` + `updateMap()` — всегда (дёшево, анимирует иконки отрядов).
3. Панели (`renderCellPanel`+`renderTab`) — только если `dirty`, либо раз в 4 тика для живых
   таймеров, **и только если** сейчас нет клика мыши (`pointerDown`) и фокус не на элементе
   ввода внутри панелей (`activeInPanels()`). Это защищает от «проглоченных» кликов.

`simMinute()` (одна игровая минута): доход → погода → падение сил пропавшего и проверка проигрыша
→ `stepUnit(u)` для каждого отряда → продвижение очереди экспертиз → случайное событие по таймеру.

## Рендер

- `buildMap()` — один раз строит сетку `#map`: подписи столбцов/строк + клетки. На каждую клетку
  создаётся DOM с дочерними `.ter` (топознак местности через CSS-фон по классу `t-<terrain>`),
  `.heat`, `.mk` (маркеры), `.uu` (иконки отрядов), `.cv>i` (полоса «осмотрено»). Ссылки на узлы
  кешируются в `cellEls[y][x]` с полями `_mk`/`_uu` для diff.
- `updateMap()` — каждый тик обновляет только изменившееся: класс клетки (выбор/вне связи),
  полосу покрытия, тепловую подсветку, маркеры (`.mk`: база/ТПК/стрелки улик/след/жертва) и иконки
  отрядов (`.uu`). Маркеры и иконки — `<img>` из `images/` (см. assets.md); сравнение строк
  `_mk`/`_uu` не даёт лишних перезаписей DOM.
- `render(force)` — шапка + карта; при `force` перерисовывает и панели, сбрасывает `dirty`.
- `touch()` — вызывать после любого изменения состояния из действий/событий. Ставит `dirty` и
  сразу перерисовывает, **если** нет активного клика/ввода (иначе отложит до `pointerup`).
- Панели: `renderHQ` (штаб/наём), `renderUnits` (отряды), `renderClues` (улики), `renderCase`
  (дело/приметы), `renderLog` (журнал), `renderCellPanel` (выбранный квадрат + отправка отрядов).

## Ввод

`bindEvents()` вешает **делегированные** слушатели на `document`:
- `click` → по `data-action` (`tab/speed/help/settings/heat/hire/build/train/recall/send/mark/exp/
  start/resume/next/hardreset/restart`). При `G.over` разрешены только `next/hardreset/restart/tab`.
- `change` → чекбоксы выбора отрядов (`selunit` → `G.ui.selUnits`) и радио длительности (`dur`).
- `pointerdown/up` → флаг `pointerDown` для защиты панелей от перерисовки во время клика.

Поскольку слушатели на `document`, они переживают пересоздание дела (`startCase`) без переподписки.

## Инициализация и запуск дела

Внизу скрипта — `try{ campaign=loadCampaign(); newGame(campaign); buildMap(); bindEvents(); …;
showIntro(true); setInterval(tick,250); } catch(err){ …экран «не удалось развернуть»… }`.

`startCase()` (кнопка «Следующее дело») и `doHardReset()` («Новая игра») генерируют новое `G` из
`campaign` и заново строят карту, не трогая подписки на события.
