# Проверка без браузера

> **Svelte-версия (корне репозитория):** тесты движка переехали на **vitest** — `npm test`
> (`src/test/*.test.ts`, node-окружение, прямой импорт `../engine`, in-memory `KV` для кампании).
> Типы — `npm run check`. Скриншоты — тот же headless Chrome по `npm run preview` (или dev-серверу).
> Ниже — оригинальный подход для легаси-файла `rescue-hq.html` (актуален как справка по приёмам).

Бэкенда нет, но проверять логику и внешний вид можно локально на `node` + headless Chrome. Три
уровня: синтаксис → логика/баланс → визуал.

## 1. Синтаксис JS
Извлечь скрипт из HTML и прогнать `node --check`:
```bash
awk '/<script>/{f=1;next}/<\/script>/{f=0}f' rescue-hq.html > game.js
node --check game.js
```

## 2. Логика и баланс (headless-харнесс)
Идея: загрузить `game.js` в песочницу `node:vm` с **заглушками DOM и localStorage**, после чего
дёргать внутренние функции. Скрипт при загрузке уже гоняет `newGame/buildMap/render` против
заглушек — если это не падает, значит путь инициализации (в т.ч. вся отрисовка) не бросает
исключений.

Харнесс лежит в репозитории — `legacy/harness.js`. Делает три теста:
1. **Генерация** — тысячи вызовов `tryGen(camp)`: доля вырожденных, длины маршрута, число
   артефактов/мусора, дистанция и жизнь жертвы, покрытие тропы радиусом связи.
2. **Авто-игрок** — прогоняет партии двумя стратегиями (компетентной и наивной), считает процент
   побед, среднее время, остаток сил и **число исключений** за всю симуляцию.
3. **Кампания** — строит штаб, обучает отряд, завершает дело победой, начинает следующее и
   проверяет перенос построек/ростера/уровней, сброс усталости, новую локацию, свежий бюджет,
   запись и очистку `localStorage`.

Ключевые приёмы для повторения харнесса:
- Экспонировать внутренности: в конец загружаемого кода дописать
  `globalThis.__api = { get G(){return G}, newGame, tryGen, simMinute, dispatchUnit, actBuild, … }`
  — в `vm`-скрипте это видит все `const`/`function` файла.
- Заглушка узла DOM — объект, у которого любой метод (`appendChild/querySelector/addEventListener…`)
  — no-op, `children.length=0`, `style` — Proxy, `classList` — заглушки. `document.createElement`/
  `querySelector` возвращают такой узел. `localStorage` — объект над обычным `{}`. `setInterval` —
  no-op (иначе `tick` будет тикать в фоне). `confirm` → `true`.
- `Date.now/Math.random` в самой игре не завязаны на детерминизм — для агрегатов это не важно.

Запуск (из корня проекта):
```bash
awk '/<script>/{f=1;next}/<\/script>/{f=0}f' rescue-hq.html > game.js
node legacy/harness.js game.js
```
Ожидаемо: 0 исключений, ~70% побед у компетентной стратегии, 0% у наивной, все проверки кампании — OK.

## 3. Визуальная проверка (headless Chrome)
Chrome умеет делать скриншот страницы без окна:
```bash
CHROME="/c/Program Files (x86)/Google/Chrome/Application/chrome.exe"
"$CHROME" --headless --disable-gpu --hide-scrollbars --force-device-scale-factor=2 \
  --screenshot=out.png --window-size=1400,900 \
  "file:///C:/…/rescue-hq.html"
```
Нюансы:
- Скриншот статичный (без кликов). Чтобы увидеть не-стартовое состояние, делают **временную копию**
  HTML в той же папке (чтобы `images/` резолвились) и через `sed` подменяют строку `showIntro(true);`
  на инъекцию: убрать модалку, при желании `dispatchUnit(...)`, сменить `G.ui.tab`, `render(true)`.
  После скриншота копию удалить.
- Панель вкладок (`#side`) начинается после широкой колонки карты — для её захвата нужно широкое
  окно (≥1120px).
- Для проверки иконок отдельно — собрать простой HTML-монтаж со всеми SVG на тёмном фоне и
  отрендерить тем же способом.

Прочитать полученный PNG можно инструментом чтения файлов (изображение показывается визуально).

## Что проверять после правок
- Тронул логику/числа → прогнать харнесс (тесты 1–3).
- Тронул разметку/CSS/иконки → скриншот игры (и при необходимости монтаж иконок).
- Всегда → `node --check`.
