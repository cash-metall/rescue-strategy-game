# Проверка без браузера

Три уровня: **типы** → **логика и баланс** → **визуал**. Бэкенда нет, поэтому всё гоняется локально
на node и headless Chrome.

```bash
npm install          # обязательно: vitest и svelte-check — devDependencies
npm run check        # типы: svelte-check, должно быть 0 ошибок
npm test             # движок: vitest run, 5 файлов / 49 тестов, ~16 с
npm run build        # второй тип-гейт: падает на ошибках компиляции Svelte
```

## 1. Типы — `npm run check`

`svelte-check --tsconfig ./tsconfig.json`. `tsconfig.include` покрывает `src/**/*.ts`, `src/**/*.d.ts`,
`src/**/*.svelte` и `vite.config.ts` — то есть **тесты тоже проверяются типами**, и сломанный тест
роняет этот гейт.

Важно: **vitest типы не проверяет** (esbuild просто срезает их). Поэтому поломка сигнатуры в движке
может пройти `npm test` зелёной и упасть только на `npm run check`. Гоняйте оба.

`node --check` в этом проекте бесполезен: `src` — это TypeScript и `.svelte`, а не plain JS.

## 2. Логика и баланс — `npm test`

Конфиг vitest лежит **внутри `vite.config.ts`**, отдельного `vitest.config.*` нет:

```ts
test: { environment: 'node', include: ['src/test/**/*.test.ts'] }
```

Отсюда два следствия: тест вне `src/test/` или без суффикса `.test.ts` **молча не запустится**, а
скрипт `npm test` = `vitest run --passWithNoTests` — при сломанном glob'е выйдет с кодом 0. Если
проверяете, что тесты вообще идут, смотрите на число прогнанных файлов, а не на код возврата.

Окружение — `node`, без jsdom. Компонентных тестов нет вообще: ничто не покрывает
`state/game.svelte.ts`, `state/fx.svelte.ts` и тик-луп в `App.svelte`.

**Из-за этого сам ТЕМП времени приходится проверять глазами.** Он задаётся одной константой
`GAME_MIN_PER_SEC = 2` в `state/game.svelte.ts` и множителем `timeScale`; 1× / 2× / 4× = 2 / 4 / 8
игровых минут на реальную секунду. Замедлять игру пропуском кадров или троттлингом
`requestAnimationFrame` **нельзя** — только этой константой. Признак правильной реализации: в
`src` нет ни одного `setInterval`, `tick(dt)` зовётся каждый кадр, а скорость входит в формулу ровно
один раз — множителем в накопителе.

**А вот плавность движения глазами проверять больше не нужно — это `motion.test.ts`.** Позиция отряда
стала чистой функцией времени (`unitFloat(g, u, tNow)`), поэтому «иконка не телепортируется» — это
утверждение о движке. Тест гоняет дело с покадровой выборкой (раз в четверть минуты) и требует, чтобы
шаг любого отряда не превышал `STEP_MAX = 0.5` клетки; отдельные тесты проверяют стыки фаз — разворот
с маршрута, возврат с осмотра, переход собаки по следу, высадку и подбор «Ветром». Раньше все эти
разрывы прятались за CSS-переходом, который добросовестно проигрывал их как полёт через полкарты.

**Балансные тесты сидированы.** `autoplayer.test.ts` и `mechanics.test.ts` подменяют случайность
через шов `setRng` на `mulberry32` с фиксированным сидом и возвращают `resetRng()` в `afterAll`. Без
этого пороги флакуют от запуска к запуску, и «регресс баланса» невозможно отличить от неудачной серии
бросков. Если правите числа — прогон повторяем, и разница означает именно вашу правку.

### Как писать тест движка

Движок — чистый TS с барелем, поэтому никаких заглушек DOM не нужно:

```ts
import { newGame, simMinute, actBuild, memoryKV, SAVE_KEY, DEFAULT_CAMPAIGN, type Fx } from '../engine';

const noop = (_fx: Fx) => {};          // Sink: глотаем тосты и запросы на сохранение
const g = newGame(DEFAULT_CAMPAIGN());
for (let i = 0; i < 500; i++) simMinute(g, noop);   // время двигаем вызовами, не таймером
```

- **`Sink`-заглушка `noop` заменяет всё стабирование тостов и DOM.** Если эффекты нужно проверить —
  собирайте их в массив вместо `noop`.
- Сохранения — через `memoryKV()` и `SAVE_KEY` из движка, `localStorage` не трогается.
- Таймеры мокать не нужно: тик-луп живёт в компонентном слое, который vitest не монтирует. Движок
  детерминирован по вызовам, а не по стенным часам.
- `setRng`/`resetRng` — шов детерминизма. `generation.test.ts` намеренно идёт на живом
  `Math.random` (там проверяется устойчивость генератора на случайных картах), а балансные наборы —
  на сидированном PRNG.

### Что проверяют существующие тесты

**`generation.test.ts`** (6 тестов, живой `Math.random`) — `N = 3000` вызовов `tryGen` в теле
`describe`, все `it` работают по одному корпусу: брак `< 20%`, годных `> 1500`; `path.length` в 5..8;
артефактов `≥ 4`; жертва внутри карты; средняя жизнь `100/drainBase` в 1800..3600 минут; инвариант
лагеря (`cheb(hq,lkp)` в 1..3, не на маршруте, **без артефактов**, не на жертве, `terrain === 'base'`);
мусора на карте нет вовсе; стартовая улика есть, но в `stats.cluesReal` не идёт.

Большая часть этого — фиксация собственных guard'ов `tryGen` (`if (path.length < 5) return null`,
`if (artCount < 4) return null`), а не эмерджентного поведения. Проверку «в клетке лагеря нет
объектов» пришлось переписать на «нет **артефактов**»: с виртуальным мусором первая формулировка стала
тривиально верной для любой клетки.

**`autoplayer.test.ts`** (2 теста, сидированный PRNG) — балансный харнесс: `while (!g.over && g.t <
MAXT)` при `MAXT = 20000`, решения каждые 10 игровых минут, ровно один `simMinute` на итерацию.
Отправляет через настоящий `actSend` (а не через низкоуровневый `dispatchUnit`), поэтому проверяются и
guard'ы действия, и авто-подхват «Ветра».

Утверждения умной стратегии (`N = 40`): `errors === 0`, просрочек по лимиту `≤ 10%`, свёрнутых дел
`< 15%`, находкой заканчивается `> 85%` дел и **`alive / N > 0.4`** — это и есть главная метрика.
Наивная стратегия (`N = 20`) успевает вовремя `< 35%`.

Почему просрочек не «ровно ноль»: если все группы выбыли по травмам, оставшийся отряд доигрывает дело
неделями. Это спроектированная «спираль травм», и живой игрок в такой ситуации нажимает «Свернуть
поиск» — эвристика бота этот момент угадывает хуже человека. Порог ловит настоящий регресс (когда дела
становятся системно недоигрываемыми — так было при первой версии, 21 дело из 40), не карая за штатный
тупик.

Чего он **не** проверяет:
- кинолога и коптер в бою — водит только пеших и один «Ветер»;
- экономику экспертизы: стратегия **читает правду** (`c.mark = c.kind === 'art' ? 'real' : 'junk'`), а
  `heatScores` работает от `effMark`, значит тепловая карта получает идеальную информацию;
- исключение внутри партии классифицируется как `error`, а не как исход (весь цикл в `try/catch`).

**`mechanics.test.ts`** (24 теста, сидированный PRNG) — точечные проверки механик. Отдельный блок
про пустые рейсы «Ветра»: машина не выезжает, если группа дойдёт раньше, чем та доедет;
разворачивается на полдороге, если подбирать стало некого; и пока за группой едет одна машина, вторую
за ней не высылают. Остальное:
проходимость и «довезти максимально близко»; путь пешего никогда не идёт через озеро; «Ветер» нельзя
отправить на осмотр; доставка без усталости и быстрее пешего; подбор на обратной дороге (группа
идёт пешком и устаёт, пока машина едет; при посадке `phaseStart` сдвигается, а время прибытия у
машины и пассажира общее — «Ветер» не может приехать раньше); дошедшую своим ходом группу машина
не ищет и возвращается пустой; «Ветры» не занимают слоты рации;
повторный проход по квадрату (и что покрытие не откатывается); качество зависит от уровня, а темп — от
условий; количество мусора по уровням (новички > 2.5, ГСН ровно 0); коптер не растит покрытие и не
создаёт улик; частота событий ≈ 30% и доля инцидентов по табличному значению уровня; вес травмы внутри
пула `< 15%`; момент события попадает внутрь задачи; проверка занятости в 06:00 не бросает группу
посреди задачи; мгновенное обучение с выбытием; ноль на таймере жизни не заканчивает дело; после конца
дела действия заблокированы.

**`motion.test.ts`** (11 тестов, сидированный PRNG) — непрерывность движения и синхронность
индикаторов. Покрытие растёт **ровно** на `coverRate` за минуту (по этому же темпу рендер доводит
змейку внутри минуты) и осмотр кончается позже прогноза `estSearch` — то есть таймер фазы для подписи
«ещё ~N мин» не годится в принципе. Дальше: склейка плеч делит время
по минутам, а не по длине (`joinTracks`); разброс иконок не зависит от соседей по клетке; разворот с
маршрута продолжается из точки разворота, а не от цели; возврат с осмотра начинается в обследованном
квадрате; собака уводит группу из её квадрата, а не из штаба; «Ветер» кончает путь на точке высадки и
не проскакивает до цели; подобранная группа и машина едут каждый от своей точки с общим временем
прибытия; вынужденная остановка держит машину и пассажиров на месте и удлиняет дорогу. Плюс полный
прогон дела с покадровой выборкой — ни одного прыжка больше `STEP_MAX = 0.5` клетки за четверть минуты.

**`campaign.test.ts`** (6 тестов) — шов `KV`: свежий `memoryKV()` на тест, постройки/наём/обучение,
затем `newGame(campaign)` и проверка переноса уровней, возврата выбывших (`away`/`busyUntil`/`restNeed`
сбрасываются), свежего бюджета `250`. Плюс докачка пешей группы до 4 уровня и закрытый 4-й у
остальных типов, три категории исходов, `resetCampaign`, битое сохранение и нормализация мусора
(`buildings: {tent: 99}`, `stats: {alive: 'x'}`, неизвестный тип юнита).

### Ожидаемые числа

`npm test` печатает только pass/fail — никакой балансной статистики. Замеры распределения исходов и
прочие агрегаты см. в [balance.md](balance.md) (раздел «Результаты прогонов»); цифры оттуда получены
этим же сидированным прогоном, так что воспроизводятся.

## 3. Визуал — headless Chrome

Собрать, поднять preview и снимать. База по умолчанию — корень (`base: '/'`), подкаталог включает
только сборка для GitHub Pages через `VITE_BASE`:

```bash
npm run build && npm run preview
CHROME="/c/Program Files (x86)/Google/Chrome/Application/chrome.exe"
"$CHROME" --headless --disable-gpu --hide-scrollbars --force-device-scale-factor=2 \
  --screenshot=out.png --window-size=1400,900 \
  "http://localhost:4173/"
```

Нюансы:
- **Ширина окна ≥ 900 px** — иначе получите мобильную раскладку, где панель вкладок закрыта
  (`translateY(110%)`) и в кадр не попадёт вовсе. Боковая колонка — `clamp(360px, 26vw, 480px)`.
- Скриншот статичный, а стартовое состояние — открытая модалка брифинга (`modal = 'intro'`).
  **Хука для инъекции состояния в текущем приложении нет**: никакого `window.__api`/`__game` `src` не
  экспортирует, бандл минифицирован с хешированными именами. Чтобы снять не-стартовый экран, нужно
  либо драйвить страницу (CDP/puppeteer, клики), либо временно поменять начальное состояние в
  исходнике (`state/game.svelte.ts`: `modal`).
- `dist/` закоммичен — легко случайно снять устаревшую сборку. Сначала `npm run build`.
- Прочитать полученный PNG можно инструментом чтения файлов — изображение показывается визуально.

## Что проверять после правок

| Что тронули | Чем проверять |
|---|---|
| Логику или числа движка | `npm test` **и** `npm run check` |
| Сигнатуры в `engine` | `npm run check` (vitest их не увидит) |
| Разметку, CSS, иконки | `npm run build` + скриншот по базовому пути |
| Траектории, фазы отряда, плавность движения | `npm test` (`motion.test.ts` ловит разрывы позиции) |
| Темп времени и скорости 1×/2×/4× | только руками в браузере — автотестов на тик-луп нет (см. выше) |
| Что угодно | оба гейта: типы зелёные, тесты зелёные |

## Приложение: легаси-харнесс

Относится **только** к однофайловой версии `legacy/rescue-hq.html` — движок `src/engine` он не видит,
и балансным гейтом живого кода больше не является. Оставлен ради Монте-Карло-статистики, которой
vitest не печатает.

Обе команды из прежней версии этого документа сегодня не работают: путь `rescue-hq.html` в корне не
существует, а корневой `package.json` объявляет `"type": "module"`, из-за чего `harness.js` падает на
`require is not defined in ES module scope`. Рабочий вариант — дать харнессу расширение `.cjs`:

```bash
awk '/<script>/{f=1;next}/<\/script>/{f=0}f' legacy/rescue-hq.html > /tmp/game.js
node --check /tmp/game.js          # синтаксис легаси-скрипта
cp legacy/harness.js /tmp/harness.cjs
node /tmp/harness.cjs /tmp/game.js
```

Харнесс стабит DOM (`fakeNode`, `Proxy` на `style`), `localStorage`, таймеры и `confirm`, дописывает
`globalThis.__api = {...}` к исходнику и запускает всё в `vm.createContext`. Его `__api` до сих пор
экспортирует `endGame`, которого в `src/engine` уже нет (разделён на `finalizeOver` и `onCaseEnd` в
сторе), поэтому нацелить харнесс на TS-движок без переписывания нельзя.

Что он печатает (замер при последнем прогоне): генерация — 7.4% брака, маршрут 5–8 (в среднем 6.5),
артефактов минимум 4 (в среднем 7.1), жизнь жертвы 1750–3406 минут; авто-игрок — 65% побед у
компетентной стратегии, 0% у наивной, 0 исключений; кампания — все 12 проверок ОК.

Для скриншотов легаси-файла старый приём с `sed` по строке `showIntro(true);` по-прежнему работает —
в Svelte-версии такой функции нет.
